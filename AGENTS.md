# Project Instructions for AI Agents (mr-impot-admin)

This repository operates on a modern, opinionated stack. As an AI Agent, adhere to the following architecture, conventions, and toolset.

## 1. Core Stack
- **Framework:** Next.js 16.2.2 (App Router only `app/`)
- **React:** v19.2.4 (React Server Components by default)
- **Styling:** Tailwind CSS v4, `clsx`, `tailwind-merge` (via `cn()` in `lib/utils`)
- **UI Components:** `shadcn/ui` and `radix-ui`
- **Icons:** `lucide-react`
- **Forms & Validation:** `react-hook-form`, `zod`, `@hookform/resolvers`
- **Internationalization (i18n):** `next-intl`
- **Animations:** `framer-motion` and `tw-animate-css`
- **Notifications:** `sonner`

## 2. Directory Structure & Conventions
- `app/[locale]/`: Root structure. Every route is localized.
- `app/[locale]/(auth)/`: Route group for authentication (`login`, `forgot_password`, `reset_password`).
- `components/ui/`: Dumb reusable UI components generated by shadcn. Do not modify these directly unless requested.
- `components/macro_componets/`: Larger composite components (e.g., `localeswitcher.tsx`).
- `lib/validations/`: Zod schemas for form state and validation (e.g., `auth.ts`). Keep logic separate from components.
- `i18n/`: Setup for Next-Intl.
- `messages/`: Translation JSONs (`en.json`, `fr.json`).
- for fake data is good to create a `data/` folder where we can regroup all our fake data

## 3. Development Guidelines
- **Server vs Client Components:** Use Server Components by default. Add `"use client"` **only** when necessary (e.g., handling state, events, `framer-motion`, interactive forms).
- **Forms:** Always use `react-hook-form` coupled with `zod`. Define Zod schemas inside `lib/validations/`. Also use `sonner` fron shadcn to show errors about validation in a toast
- **Styling classes:** Handle complex tailwind class merging exclusively with the `cn()` utility exposed in `lib/utils.ts`.
- **Localization:** Never hardcode text literals in components. Retrieve them using `next-intl` hooks (`useTranslations`) and keep `en.json` and `fr.json` in sync.
- **Paths:** Always use absolute imports where configured (e.g., `@/components/...`).
- **Internationalisation** Always verify that all text can be internationalize
- **Code structure** Always check if create components is necessary to modulate the code
